# Atlas 디자인 규칙

Atlas는 에이전트 세션을 검토하는 개발 도구다. 화면은 다음 개선 작업의 문제·조치·검증을 빠르게 비교할 수 있어야 한다. 근거는 판단할 때만 여는 상세 정보다. 마케팅 문구나 장식보다 정보의 출처와 상태를 우선한다.

[다크 세션 검토](assets/atlas-dashboard-review.png) · [라이트 세션 검토](assets/atlas-dashboard-review-light.png) · [모바일 세션 검토](assets/atlas-dashboard-review-mobile.png) · [다크 설정 예시](assets/atlas-settings-dark.png) · [라이트 설정 예시](assets/atlas-settings-light.png) — 합성 데이터로 검증한 화면.

## 시각 방향

- 다크 테마는 거의 검정에 가까운 잉크 캔버스와 청색 계열 표면을 사용한다. 중립 회색만으로 화면을 만들지 않는다. 사이드바 시작·끝과 아바타 끝 색은 공통 토큰으로 두고, 라이트 테마에서는 같은 토큰을 밝은 표면으로 바꾼다.
- 색은 역할을 전달할 때만 쓴다. 캔버스·사이드바·요약 스트립에는 깊이를 위한 낮은 대비의 청색 radial/linear gradient를 한 겹만 쓸 수 있다. 상태와 데이터 행에는 장식용 gradient를 쓰지 않는다.
- 패널은 8–10px 반경과 1px 경계선을 기본으로 하며, 페이지와 분리해야 할 때만 낮은 대비 그림자를 쓴다. 모든 정보를 카드로 나누지 않는다.
- 세션 목록이 첫 화면의 중심이다. 요약 지표는 하나의 스트립으로 묶고 상세 내용은 `발견 사항 → 다음 개선 작업` 순서로 배치한다. 용량·이벤트·토큰 메트릭은 기본으로 접힌 native disclosure에 둔다.
- 분석 결과의 주 화면에는 근거 타임라인을 상시 표시하지 않는다. 개선 작업은 `문제 / 조치 / 검증` 열로 비교하고, 각 근거 ID에서 대화상자를 연다.
- 사이드바는 넉넉한 여백과 7px 이상 선택 표면으로 현재 위치를 명확히 보인다. 표는 조밀한 헤더·tabular 숫자·행 hover로 많은 기록을 빠르게 훑게 한다. 주 행동은 파란 채움 버튼 하나, 나머지는 테두리 버튼으로 위계를 만든다.
- Noto Sans KR을 기본 글꼴로 사용한다. 코드, 세션 ID, 모델 ID는 시스템 고정폭 글꼴을 사용한다.

## 색상 역할

| 역할    | 다크      | 라이트    | 사용처                       |
| ------- | --------- | --------- | ---------------------------- |
| Canvas  | `#090B12` | `#F4F7FB` | 페이지 배경                  |
| Surface | `#111521` | `#FFFFFF` | 패널과 사이드바              |
| Raised  | `#181E2D` | `#E9F0F8` | 입력과 선택 가능한 보조 표면 |
| Cobalt  | `#6699FF` | `#2563EB` | 주 행동, 링크, 진행 중       |
| Teal    | `#39C6B3` | `#087F76` | 브랜드, 탐색 선택, 성공 계열 |
| Violet  | `#A78BFA` | `#6D4BD1` | AI 발견 사항과 근거 연결     |
| Amber   | `#F0B95B` | `#A15C08` | 개선 후보                    |
| Rose    | `#FB7185` | `#C42F45` | 실패와 삭제                  |

색상만으로 상태를 전달하지 않는다. 상태점에는 텍스트를 붙이고, 선택 행에는 색면과 왼쪽 선을 함께 쓴다.

## 타이포그래피와 간격

| 요소              |      크기 |    굵기 |
| ----------------- | --------: | ------: |
| 페이지 제목       |      28px |     700 |
| 섹션 제목         | 14px 이상 |     600 |
| 본문과 버튼       |      14px | 400–600 |
| 캡션과 메타데이터 | 12px 이상 | 400–600 |
| 코드              |   12–14px |     400 |

기본 간격 단위는 4px이다. 조밀한 목록은 8–12px, 패널 내부는 16–24px, 페이지 구간은 24–32px을 사용한다. 설명을 추가해 밀도를 낮추기보다 레이블과 열 정렬을 명확하게 한다.

## 화면 경로와 공통 구현

| 경로        | 화면                     |
| ----------- | ------------------------ |
| `/sessions` | 세션 검토·근거           |
| `/analyses` | 분석 작업·진행 상태      |
| `/settings` | 개인 설정·모델·Collector |

세션 목록의 페이지·개수·검색어는 URL 쿼리에 유지한다. 전체 지표를 현재 페이지 집계처럼 표시하지 않는다. 목록은 계정 타임존과 초 단위로 `접수 시작`과 `접수 완료`를 분리한다. Collector가 caught-up을 선언하지 않은 세션의 완료 시각은 `—`로 표시하며, 마지막 배치 수신 시각을 완료로 부르지 않는다. 대기·재시도·실제 요청 중을 구별한다.

새로고침·뒤로 가기·직접 접근은 같은 화면을 유지한다. 루트 URL은 `/sessions`로 이동하며 기존 세션·Collector 연결 링크의 쿼리를 보존한다. 페이지 이동은 Next.js Link를 사용하고 활성 메뉴에 `aria-current`를 표시한다.

공통 화면은 `apps/web/components/atlas.tsx`, 선택 메뉴는 `components/select.tsx`, 디자인 토큰은 `app/globals.css`에서 관리한다. 제품 이름과 `Agent Observatory`는 왼쪽 위에 두고 브랜드 설명은 한 줄로 표시한다. 리전·버전은 바로 아래 제품 정보에 묶는다. 로그인·계정은 구분선 아래 별도 영역에 둔다. 모바일에서도 같은 정보 위계를 유지한다. 포커스를 되찾으면 인증을 새로 확인하고, 계정이 바뀌면 이전 계정의 화면 데이터와 입력한 API key를 제거한다.

## 컴포넌트

- 메뉴는 문자 기호 대신 동일한 24px 격자·1.75px 선의 SVG 아이콘을 사용한다. 세션은 대화, 분석 기록은 보고서, 설정은 톱니바퀴로 표현한다. 원본은 `components/navigation-icon.tsx`에서 관리한다.
- 분석 결과의 Free tier/BYOK·Provider·모델·비용은 결과 상단에 한 번만 표시한다. 하단에 반복하지 않는다.

- 주 버튼은 두 테마 모두 `#2563EB` 배경과 흰 글자를 사용한다. 한 구역에 하나만 둔다.
- 보조 버튼은 투명 배경과 명확한 경계선을 사용한다.
- 세션 테이블은 행 전체를 읽을 수 있게 유지한다. 선택 행은 teal, 실행 상태는 상태별 색으로 구분한다.
- AI 발견 사항과 연결된 근거 ID는 violet 링크다. 클릭하면 native dialog에서 종류·시각·도구/이름·사람이 읽을 원문·해시를 확인한다. Escape와 배경 클릭으로 닫히고, 닫은 뒤 원래 근거 링크로 focus를 돌린다. 원본 JSON은 접힌 disclosure로만 둔다.
- 근거 해시는 `normalized_event` 또는 `stored_excerpt` 범위를 함께 표시한다. 이전 결과에 해시가 없으면 가짜 값을 만들지 않고 `해시 없음`으로 표시한다. 연결된 ID의 저장 근거가 없을 때도 누락 상태를 표시한다.
- 개선 작업은 amber 왼쪽 선과 옅은 배경으로 표시한다. AI 결과에는 문제·조치·검증을 나란히 두며, 구 형식의 `text`만 저장된 결과는 관찰로 유지하고 빈 구조를 추정하지 않는다.
- 결정적 규칙 결과는 violet 관찰로 표시한다. 규칙 ID·버전·횟수와 한계를 함께 보여 주며, 규칙 신호를 문제·수정 필요성의 증거로 표현하지 않는다.
- 각 개선 작업은 에이전트에 넘길 작업을 복사할 수 있다. 복사본에는 세션·분석 결과·규칙 ID/버전·근거 ID/해시와, 실행하면 안 되는 신뢰할 수 없는 원문임을 포함한다. 이 동작은 복사만 하며 작업을 자동 실행하거나 상태를 저장하지 않는다.
- 명령은 고정폭 코드 블록과 같은 높이의 복사 버튼을 한 행에 둔다. 복사 성공과 실패를 즉시 알린다.
- 드롭다운은 공통 `Select` 컴포넌트를 사용한다. 선택 표식, 방향키·Home·End·Enter·Escape·Tab, 바깥 클릭 닫기, focus와 listbox 관계를 함께 유지한다.
- 모델 후보는 서버 설정 순서를 유지한다. Provider와 정확한 모델 ID를 표시하되, 목록을 현재 연결 상태나 가용성으로 표현하지 않는다.
- 설정 패널은 같은 최대 너비를 사용한다. 레이블 열과 입력 열을 맞추고, 좁은 화면에서 한 열로 전환한다.

## 제품 용어

한국어 문장을 기본으로 하되 익숙한 제품·API 용어는 아래 표기를 고정한다.

| 개념                  | 표기                     |
| --------------------- | ------------------------ |
| 서비스 제공 무료 모델 | Free tier                |
| 개인 제공 키          | BYOK                     |
| 모델 제공 서비스      | Provider                 |
| API 접속 주소         | Endpoint                 |
| 인증 키               | API key                  |
| 수집 프로그램         | Collector                |
| 관찰 기록·처리 결과   | 세션·분석·근거·개선 후보 |

`무료 티어`처럼 번역투인 표기는 피한다. 설명 문장에서는 `무료 모델`, `개인 키`처럼 자연스러운 한국어를 쓴다.

## 상태와 접근성

- hover, focus, selected, disabled 상태를 모두 정의한다. 키보드 focus에는 2px cobalt 외곽선을 사용한다.
- 본문·캡션·버튼 텍스트는 두 테마에서 배경 대비 4.5:1 이상을 유지한다. 캡션을 12px보다 작게 만들지 않는다.
- 오류는 rose, 성공은 teal/green, 진행은 cobalt를 사용하고 항상 상태 문구를 함께 표시한다.
- 다크, 라이트, 시스템 테마와 720px 이하 모바일 레이아웃을 변경마다 확인한다.
- 모델 ID와 명령은 모바일에서 줄바꿈되어야 하며 가로 화면을 밀어내면 안 된다.

## 변경 원칙

새 UI는 기존 토큰과 의미 역할을 먼저 사용한다. 새 색을 추가하려면 기존 역할로 표현할 수 없는 상태인지 확인하고 이 문서를 함께 갱신한다. 카드, 배지, 그라디언트를 반복해 정보를 꾸미지 않는다. 실제 데이터의 길이, 빈 상태, 실패 상태, 근거 누락 상태를 합성 데이터로 확인한다.
